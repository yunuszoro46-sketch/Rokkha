# Dhaka administrative boundaries

`dhaka_boundaries.geojson` holds Dhaka District (admin level 2) and the
7 upazilas / city corporations inside it (admin level 3).

| pcode | Name | Level |
|---|---|---|
| BD3026 | Dhaka (District) | 2 |
| BD30260014 | Dhamrai | 3 |
| BD30260018 | Dohar | 3 |
| BD30260038 | Keraniganj | 3 |
| BD30260062 | Nawabganj | 3 |
| BD30260072 | Savar | 3 |
| BD30262000 | Dhaka South City Corporation | 3 |
| BD30262500 | Dhaka North City Corporation | 3 |

## Source and license

- **Source:** Bangladesh Bureau of Statistics (BBS)
- **Contributed by:** OCHA Regional Office for Asia and the Pacific (ROAP)
- **Published by:** OCHA Field Information Services Section (FISS) and the Humanitarian Data Exchange (HDX)
- **URL:** https://data.humdata.org/dataset/cod-ab-bgd

- **Valid on:** 2023-05-21 (dataset reviewed June 2025)

Attribution: *Administrative boundaries © Bangladesh Bureau of Statistics (BBS)
and UN OCHA, via the Humanitarian Data Exchange, licensed under CC BY-IGO.*

## Changes made from the original

- Kept only Dhaka District (`adm2_pcode = BD3026`) and its admin level 3 units.
- Renamed properties to `name`, `pcode`, `admin_level`, `parent_name`,
  `parent_pcode`, `area_sqkm`, `valid_on`, `version`.
- Rounded coordinates to 6 decimal places (about 0.1 m).

Regenerate with `scripts/extract_dhaka_boundaries.py` (see its docstring).

## Known limitations

- **No ward boundaries.** HDX states ward-level (admin 4) boundaries are not
  officially confirmed or maintained, so they are not included.
- Boundary alignment follows BBS as of March 2025; other sources
  (e.g. OpenStreetMap) may differ slightly.

# Bangladesh districts (national)

`bangladesh_districts.geojson` holds all **64 districts** (admin level 2)
of Bangladesh from the same HDX COD-AB v03 dataset (same source, license
and attribution as above). It is used by the flood-history module
(`data/flood/`) to answer "which district is this?" anywhere in the country.

Changes from the original:

- Simplified with a 0.0005° tolerance (Shapely, topology preserved) to keep
  the file under 1 MB. Largest border shift measured: about 72 m; largest
  area change: 0.05 %. Use `dhaka_boundaries.geojson` for precise work
  inside Dhaka District.
- Coordinates rounded to 5 decimal places (about 1 m).
- Same property names as above (`name`, `pcode`, `admin_level`,
  `parent_name`, `parent_pcode`, `area_sqkm`, `valid_on`, `version`);
  here the parent is the division.

Generated by `scripts/build_flood_data.py`.

# All upazilas of Bangladesh (for readable place names)

`bangladesh_upazilas.geojson` holds the **507 upazilas** (admin level 3) of the **same release as the districts
above** (HDX COD-AB v03, BBS / OCHA, valid on 2023-05-21, CC BY-IGO). It turns a GPS point into a readable name
such as "Tahirpur, Sunamganj" (`GET /geospatial/place-name`). The lookup runs on our own server: coordinates are
never sent to an outside geocoding service.

- **Properties:** `name`, `pcode`, `admin_level` (3), `parent_pcode` / `parent_name` (district),
  `division_pcode` / `division_name`, `valid_on`, `version`.
- **Changes:** coverage-aware simplification (`shapely.coverage_simplify`, tolerance 0.0005, shared borders kept
  identical, nothing dropped), 5 decimals (about 1 m).
- **Generated by** `scripts/build_map_geography.py`, which also writes the portal's map geography
  (`Frontend/public/geo`) from the same archive. Details: `docs/BANGLADESH_GEOGRAPHIC_DATA.md` in the portal.
- Replaces (19 Nov 2026) the earlier geoBoundaries ADM3 file (544 units, 2020 vintage, names only): a different
  release from the districts, without stable codes.

Attribution: *Upazila boundaries © Bangladesh Bureau of Statistics (BBS) and UN OCHA, COD-AB v03, via HDX,
CC BY-IGO.* A point near a border can be named after the neighbouring upazila; the name is a help for
reading, never a replacement for the coordinates rescuers use.
